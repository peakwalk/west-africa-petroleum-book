# Book 阅读界面对齐设计

**日期：** 2026-05-31

**目标**

在保留 mdBook 现有交互模型、内容生成链路和构建流程的前提下，使 `/book/` 的阅读界面在视觉和布局上对齐已确认的 `figma-prototype` 阅读页。

**参考资料**

- 原型源码：`temp/figma-prototype/src/app/pages/ReadingPage.tsx`
- 原型主题变量：`temp/figma-prototype/src/styles/theme.css`
- 原型部署地址：`https://candy-zebra-72648958.figma.site/read`
- 当前阅读壳模板：`theme/index.hbs`
- 当前阅读样式与行为：`theme/custom.css`、`theme/custom.js`

## 背景

当前 `/book/` 已经具备本次所需的大部分信息架构：

- 顶部吸顶工具栏
- 左侧章节导航栏
- 中间正文阅读列
- 右侧 “On This Page” 导航栏
- 阅读进度指示器
- 上一章 / 下一章导航

问题不在于架构缺失，而在于与已批准原型相比，当前页面在布局保真度、间距、密度、组件处理方式以及整体阅读壳质感上仍有明显差距。

因此，本次工作不应重写阅读系统。正确策略是对现有 mdBook 阅读壳进行重塑，使其呈现效果接近原型，同时不破坏 mdBook 的既有能力。

## 范围

本次包含：

- `/book/` 阅读界面壳层
- 吸顶页头的布局与样式
- 左侧章节导航栏的展示方式
- 中间阅读列的布局与排版处理
- 右侧 “On This Page” 导航栏的展示方式
- 阅读进度条的视觉处理
- 上一章 / 下一章卡片样式
- 仅针对阅读壳的响应式行为

本次不包含：

- 落地页重设计
- 搜索页重设计
- `toc.html` 或章节索引页重设计
- `print.html` 重设计
- 章节内容或 Markdown 结构改动
- 引入原型中的新路由，如 `/search`、`/chapters`、`/countries`、`/fiscal`
- 将原型的 React/Vite 运行时迁入本项目

## 约束

实现必须保留以下前提：

- mdBook 仍然是内容生成引擎
- 章节内容仍来自 `src/**/*.md`
- 左侧导航仍由 `SUMMARY.md` 生成
- 右侧节级导航仍由章节标题自动生成
- 搜索、主题切换、打印、仓库链接、编辑链接保持现有行为
- 现有构建命令继续可用

实现不得要求直接编辑 `book/` 或 `public/book/` 中的生成产物。

## 设计决策

### 1. 保留 mdBook 行为，只替换阅读壳处理方式

项目继续保留 mdBook 的语义结构、关键 id、生成内容挂载点和控件行为，不尝试把阅读界面重建成一个 React 页面。

具体做法：

- 继续使用 `theme/index.hbs` 作为阅读壳入口
- 继续使用 `theme/custom.css` 作为主要样式层
- 继续使用 `theme/custom.js` 承担少量 DOM 连接和滚动增强逻辑

这样可以在控制风险的同时，获得足够高的视觉保真度。

### 2. 对齐原型定义的阅读心智模型

原型建立了一套清晰的阅读页结构模型：

- 紧凑型吸顶工具栏
- 桌面端持续存在的左侧章节导航
- 居中的正文阅读卡片
- 安静、辅助性的右侧页内导航栏
- 细而克制的阅读进度线
- 轻量的章节切换卡片

mdBook 阅读页将采用同样的结构模型，即使底层 DOM 不完全一致。

### 3. 保留内容驱动导航，不复制原型中的静态假数据

原型中章节列表和页内目录是写死的数组，生产环境不能这样处理，必须继续真实反映书籍内容。

因此，本次所谓“对齐”定义为：

- 布局层级一致
- 视觉密度一致
- 卡片与面板处理方式一致
- 间距和排版节奏相近

本次不以复制原型中的占位数据或路由系统为目标。

## 拟实施方案

### 修改文件

- `theme/index.hbs`
- `theme/custom.css`
- `theme/custom.js`

### `theme/index.hbs`

只做小幅结构调整，保留 mdBook 集成点不变。

更新后的目标结构：

- 三段式页头
  - 左侧：侧栏开关 + 品牌入口
  - 中间：阅读上下文标签 + 书名
  - 右侧：mdBook 操作按钮组
- 页头下方直接放置进度条
- 三栏内容壳
  - 左侧：mdBook 生成的章节导航
  - 中间：正文卡片 + 上下章导航卡片
  - 右侧：迁移后的 “On This Page” 内容

模板中以下关键点不改：

- `{{{ content }}}`
- 搜索容器相关 id 和控件
- 主题切换相关 id 和控件
- 左侧导航容器 id
- previous / next 章节数据使用方式

### `theme/custom.css`

这个文件将成为本次视觉保真度的主要来源。

需要达到的样式结果：

- 顶部工具栏在视觉上接近原型的紧凑阅读栏
- 工具按钮拥有统一的 icon button 尺寸和 hover 反馈
- 工具栏中间区在桌面端恢复存在感，在小屏端能自然折叠
- 左侧章节导航呈现为结构化导航面板，而不是原始 mdBook 默认样式
- 当前章节保持主色实底高亮
- 章节分组标题更轻、更紧凑、更像标签
- 右侧导航栏更像辅助面板，而不是第二个主栏
- 正文内容通过白色卡片、柔和边框、更大的内边距和轻阴影成为视觉中心
- 标题、正文、表格、引用、图片等的间距节奏接近原型阅读体验
- 进度条更细、更克制
- 上下章卡片更轻、更紧凑，更贴近原型构成

### `theme/custom.js`

JavaScript 保持轻量，只为阅读壳服务，而不定义产品逻辑。

它应继续负责：

- 如果自定义布局仍然需要，则保留内部滚动桥接
- 将生成出的 “On This Page” 节点移动到右侧容器
- 基于真实滚动容器更新阅读进度条
- 保证内部滚动容器下的 hash 链接滚动稳定

如果在 CSS 和模板更新后，当前某些桥接逻辑已不再需要，应删除，而不是机械保留。

## 响应式策略

桌面端保真度优先，但响应式可用性必须稳定。

### 大桌面

在较宽屏幕下，页面应呈现完整三栏阅读布局：

- 左侧导航可见
- 中间正文卡片有稳定最大宽度
- 右侧 “On This Page” 导航可见

这是最接近原型的状态。

### 中等宽度

在中等宽度下，应优先隐藏右侧辅助栏，以保证正文阅读宽度。左侧导航继续保留，因为它仍然是主导航工具。

### 窄屏与平板

左侧导航继续保持可折叠，而不是永久显示。正文区域切换为单列阅读，页头在必要时变得更紧凑，但不彻底换成另一套结构。

### 手机端

阅读列变为完整单列：

- 页面左右内边距更小
- 正文卡片内边距减小
- 标题字号下调
- 上下章卡片改为纵向堆叠
- 右侧辅助栏隐藏

最终结果仍应让人感觉这是同一个产品，而不是一套单独的移动端页面。

## 风险与缓解

### 风险：mdBook 默认样式与自定义阅读壳冲突

缓解方式：

- 只定向覆盖阅读壳相关选择器
- 保留 mdBook 原有关键 id 和容器
- 避免宽泛 reset 影响其他生成页面

### 风险：内部滚动处理破坏 hash 跳转或进度计算

缓解方式：

- 让进度和锚点逻辑始终绑定真实滚动容器
- 测试直接 hash 访问和页内标题跳转
- 如果布局不再需要桥接代码，就移除不必要逻辑

### 风险：内容较重的章节暴露溢出问题

缓解方式：

- 保留表格横向滚动能力
- 保留图片最大宽度约束
- 至少测试一个长章节和一个表格较多的章节

## 验收标准

- `/book/` 在视觉方向上对齐已批准的原型阅读页
- 页面继续保留 mdBook 的侧栏开关、搜索、主题切换、打印、仓库、编辑等交互
- 左侧章节导航、中间正文卡片、右侧 “On This Page” 导航在桌面端形成一致的三栏阅读壳
- 阅读进度条在滚动时正确更新
- 上一章 / 下一章导航保持可用
- 平板和手机宽度下的响应式行为仍然可用
- `npm run build` 成功，且不需要手改生成产物

## 验证计划

1. 更新主题源文件中的模板、CSS 和 JS。
2. 运行现有构建命令。
3. 检查至少一个长篇章节和一个表格较多的章节。
4. 验证：
   - 页头布局
   - 侧栏开关
   - 搜索控件可见性与行为
   - 主题切换行为
   - 右侧页内目录位置
   - 进度条更新
   - 上下章链接
5. 如果需要做视觉比对，再用 Playwright 对本地阅读页和原型部署页做截图比较。
