# Book 底部章节导航对齐设计

**日期：** 2026-06-12

## 目标

在不改变 mdBook 章节切换数据来源、模板语义和构建链路的前提下，将阅读页底部章节导航对齐到已讨论确认的两套视觉目标：

- wide 版：正文列内双卡横排，左右对称，接近桌面设计图
- thin 版：正文列内双卡纵排，整宽堆叠，接近窄屏设计图

本次设计的输出不是泛泛的视觉建议，而是一套可直接落到 `theme/custom.css`、`theme/custom.js` 与 `scripts/test-book-pagination-render.sh` 的完整规范。

## 决策摘要

本次采用以下结论：

- 保留现有模板结构，不新增第二套分页 DOM
- `chapter-pagination` 始终锚定正文列宽度，不再锚定图表宽度，也不再用与正文无关的卡片最大宽度推导布局
- wide 版分页容器改为两列等分布局，而不是 `space-between + 224px 小卡`
- thin 版分页容器改为上下整宽堆叠，并按设计图重设卡片高度、内边距、字号和对齐方式
- 桌面端保留等高逻辑，thin 版移除运行时等高
- wide 和 thin 的视觉差异只由断点样式驱动，不复制模板，不复制数据，不引入静态假内容

## 第一性原理

从第一性原理出发，底部章节导航的目标只有四个：

1. **帮助读者连续阅读**
   - 它的首要任务是帮助读者从当前章节平滑跳到上一章或下一章。
   - 它不是品牌展示位，也不是内容摘要卡片列表。

2. **保持阅读流的末端收束感**
   - 它必须在正文结束后形成稳定的“阅读闭环”。
   - 过小会显得像页脚碎片，过大则会压过正文。

3. **视觉上服从正文列**
   - 它必须附着在正文列的网格和节奏之内，而不是形成第二套宽度体系。
   - 任何与正文列脱锚的独立宽度约束，最终都会制造不必要的留白或挤压。

4. **内容驱动而非静态伪装**
   - 上一章、下一章、章号、标题、副文案都应继续来自真实章节元信息。
   - 设计不能要求手写静态章节文本或维护重复模板。

由此可推导出两个硬约束：

- 模板结构应尽量复用现有 `previous / next` 数据结构
- 布局应由正文列宽、断点和内容密度决定，而不是由孤立的 `224px` 或 `460px` 之类的局部常量决定

## 现状与问题

### 1. 结构层是正确的

当前模板结构已经满足分页语义要求：

- 容器是 `nav.chapter-pagination`
- 左卡使用 `previous`
- 右卡使用 `next`
- 左卡结构是 `badge -> body`
- 右卡结构是 `body -> badge`

因此，模板层不是当前问题的根源。

### 2. wide 版的问题是“正文容器正确，卡片模型错误”

当前 wide 版样式中：

- 分页容器宽度已经锚定正文列：`width: min(100%, var(--reader-article-body-width))`
- 但卡片又被限制为 `max-width: 224px`
- 容器仍然使用 `justify-content: space-between`

这会导致以下结果：

- 正文列当前解析宽度约为 `624px`
- 两张卡总宽只有 `224 + 224 + 12 = 460px`
- 剩余空间被 `space-between` 吃掉，视觉空白远大于设计图中的 `12px`

根本问题不是容器宽度，而是“容器按照正文列建模，卡片却按照独立小组件建模”。

### 3. thin 版的问题是“堆叠方向正确，但视觉密度和对齐方式错误”

当前 thin 版已经改为纵向堆叠，但仍有四类偏差：

- 卡片最小高度只有 `80px`，明显低于设计图
- `next` 卡正文在部分实现中被错误居中，破坏了上一章 / 下一章的方向性对齐
- 标签字号只有 `8px`，在窄屏视觉上偏弱
- 装饰水印和圆标过小，卡片不像设计图中的“整宽章节切换卡”

### 4. 当前 JS 等高逻辑对 thin 版不友好

当前 `syncChapterPaginationHeights()` 会对所有断点统一执行等高。

这在 wide 版是合理的，因为双卡横排需要等高；但在 thin 版中：

- 卡片是纵向堆叠
- 读者逐张读取
- 运行时等高会把短卡片强行拉高，破坏窄屏阅读节奏

因此，等高逻辑必须限制在 wide 版。

## MECE 拆解

为保证方案完整且互斥穷尽，本次问题拆为五个互不重叠的层面：

### A. 数据与语义层

- `previous / next` 章节链接
- 标题文本
- 章节编号
- 副文案 `dek`
- 无上一章或无下一章时的占位行为

### B. 布局层

- wide 版容器如何与正文列对齐
- wide 版双卡如何分配宽度
- thin 版堆叠顺序和整宽策略
- 占位块在不同断点下的显示规则

### C. 视觉层

- 卡片高度
- 内边距
- 圆角
- 边框与阴影
- 圆标尺寸
- 水印尺寸与透明度

### D. 排版层

- 标签字号与 tracking
- 标题字号与行高
- 副文案字号与行高
- 左右卡在 wide / thin 下的文字对齐

### E. 运行时与验证层

- wide 版是否等高
- thin 版是否取消等高
- 测试脚本对 wide / thin 的断言如何更新

## 方案备选

### 方案一：最小 CSS 补丁，继续沿用当前 224px 小卡

做法：

- 保留 wide 版 `224px` 小卡
- 只微调字号、padding 和 thin 版堆叠样式

优点：

- 改动最小
- 测试变更少

缺点：

- wide 版无法对齐设计图
- 会继续存在正文列与分页卡模型脱节的问题
- 视觉空白仍然是结构性缺陷，不是 token 问题

结论：

- 不采用

### 方案二：保留模板，按断点重建分页布局模型

做法：

- 保持现有 DOM 与 JS 元信息注入方式
- wide 版改为正文列内双列等分卡片
- thin 版改为整宽纵向堆叠卡片
- 只在 wide 版执行等高

优点：

- 完整解决布局模型错误
- wide 与 thin 都能接近设计图
- 风险集中在 CSS 与少量 JS，边界清晰

缺点：

- 需要同时更新测试
- 需要重新设定一组分页 token

结论：

- 推荐采用

### 方案三：为 wide 与 thin 写两套独立分页模板

做法：

- 在模板层拆出 desktop / thin 两套 DOM
- 各自单独排布

优点：

- 每个断点都能单独控制结构

缺点：

- 模板重复
- 测试复杂度升高
- 内容注入与无障碍语义容易漂移
- 不符合“结构复用、样式分化”的最小复杂度原则

结论：

- 不采用

## 推荐方案

采用方案二：**保留模板，重建分页布局模型。**

## 详细设计

### 1. 模板与语义层

`theme/index.hbs` 保持现状，不做结构调整。

保留原因：

- 当前 DOM 已经具备 wide 与 thin 所需的 badge / body 顺序
- `previous` 缺失时已有 placeholder
- `next` 卡章节编号已由 JS 注入

`theme/custom.js` 中 `applyChapterNavMeta()` 保持现有行为：

- `next` 卡优先显示章号
- 无章号时回退箭头
- `dek` 继续来自页面 lede 的首句摘要

### 2. wide 版规范

wide 版定义为：`min-width > 760px` 的阅读列分页。

#### 2.1 容器

- 宽度：`min(100%, var(--reader-article-body-width))`
- 当前解析宽度：约 `624px`
- 布局：`display: grid`
- 列：`repeat(2, minmax(0, 1fr))`
- 列间距：`12px`
- 顶部间距：`24px`

说明：

- wide 版不再使用 `justify-content: space-between`
- wide 版的两张卡应由正文列均分
- 在当前正文列宽度下，每张卡理论宽度为 `(624 - 12) / 2 = 306px`

#### 2.2 卡片

- 宽度：`100%`
- 最大宽度：取消 `224px` 限制
- 高度：移除固定 `height: 80px`
- 最小高度：`92px`
- 内边距：`12px`
- 内部 gap：`12px`
- 圆角：`12px`
- 边框：`1px solid rgba(31, 54, 95, 0.14)`
- 阴影：比当前更轻，不得压过 figure / table 卡片

#### 2.3 网格结构

左卡：

- `grid-template-columns: 44px minmax(0, 1fr) 96px`
- 左侧为圆标
- 中间为正文
- 右侧为装饰图专用缓冲区，不允许装饰图压入正文区

右卡：

- `grid-template-columns: 96px minmax(0, 1fr) 44px`
- 左侧为装饰图专用缓冲区，不允许装饰图压入正文区
- 中间为正文
- 右侧为圆标

wide 版继续保持：

- 左卡正文左对齐
- 右卡正文右对齐

#### 2.4 徽标与装饰

- 卡片背景：复用图片 card / 表格 card 的纯色背景 token，不使用蓝白渐变
- 圆标：`44px x 44px`
- 箭头字号：`24px`
- 章节数字字号：`20px`
- 左卡装饰图使用 `../../assets/images/prototype-hero-graywhite-left.png`
- 右卡装饰图使用 `../../assets/images/prototype-hero-graywhite-right.png`
- 右卡装饰图必须是左卡装饰图的水平镜像，保证两侧轮廓密度、清晰度和视觉重心一致
- 两张资产都应从原始 `prototype-hero` 图片灰度化后生成，并保留海面信息
- 装饰图缓冲列宽：wide `116px`；thin `104px`
- 装饰图框：wide `116px x 80px`；thin `104px x 80px`
- 素材 alpha：`0.48`
- 运行时装饰层 opacity：`0.30`
- 图像整体应保持高亮灰度观感，并在位图资产中直接去除近白背景，避免出现明显贴片
- 背景去除应优先基于四角 floodfill / 相近白色抠除，保留平台主体、海平线、海面层次与水面反射
- 运行时不依赖 `mix-blend-mode` 或 CSS `mask-image`，装饰层融合效果应主要由素材透明通道承担
- 贴边一侧不得保留透明空列；左卡素材的右边缘、右卡素材的左边缘必须以有效像素直接贴边
- 文本区与装饰图区之间的实际视觉间距应保持 `12px`，不得再额外预留宽屏缓冲空白
- 左卡的圆圈与文本组距离上、下、左边框均为 `12px`；右卡的文本组与圆圈距离上、下、右边框均为 `12px`
- 素材应裁薄上下透明边，使 wide / thin 两种断点下的装饰图可在视觉上接近与上下边框各留约 `12px` 的呼吸
- 装饰图资产底部必须保留足够画面内容，避免 rig 最下沿、海平线或海面反射在卡片边缘处看起来被裁掉
- 必须保留海平线、海面层次与水面反射，不能只保留 rig 剪影主轮廓
- 资产必须保留完整 rig 主体，并保持灰白 silhouette 观感，避免出现照片块或蓝色调
- wide 版装饰图贴边偏移：`0`
- 左卡装饰图贴右侧，右卡装饰图贴左侧
- 装饰图靠近卡片底边停靠，与下边框保持约 `8px` 留白，不再垂直居中
- 左右卡通过停靠位置区分，同时右卡装饰图使用左卡装饰图的水平镜像版本

#### 2.5 排版

- 标签：`11px / 13px`，`letter-spacing: 0.08em`
- 标题：`16px / 1.08`，`font-weight: 600`
- 副文案：`10px / 1.3`
- `dek` 不再限制为 `18ch`

### 3. thin 版规范

thin 版定义为：`max-width <= 760px` 的阅读列分页。

#### 3.1 容器

- 布局：纵向堆叠
- 宽度：`100%`
- 卡片间距：`12px`
- 顶部间距：建议 `16px`

#### 3.2 卡片

- 宽度：`100%`
- 高度：`auto`
- 最小高度：`92px`
- 内边距：`12px`
- 内部 gap：`12px`
- 圆角：`12px`
- 背景：复用图片 card / 表格 card 的纯色背景 token，不使用蓝白渐变

#### 3.3 左卡

- `grid-template-columns: 44px minmax(0, 1fr) 104px`
- 左侧为圆标
- 中间为正文
- 右侧为空白缓冲区，留给水印和视觉呼吸
- 正文左对齐

#### 3.4 右卡

- `grid-template-columns: 104px minmax(0, 1fr) 44px`
- 左侧为空白缓冲区，留给水印
- 中间为正文
- 右侧为圆标
- 正文右对齐

#### 3.5 徽标与装饰

- 圆标：`44px x 44px`
- 箭头字号：`24px`
- 章节数字字号：`20px`
- 水印：`104px x 80px`
- 水印在卡片底边上方约 `8px` 停靠，与上下边框保持接近 `12px` 的稳定留白
- 透明度：`0.36`

#### 3.6 排版

- 标签：`12px / 14px`
- 标题：`16px / 17px`
- 副文案：`10px / 13px`
- `next` 卡标题与副文案右对齐
- `previous` 卡标题与副文案左对齐

#### 3.7 占位行为

- thin 版继续隐藏 `.chapter-nav-placeholder`
- 不为单卡场景保留空位

### 4. JS 行为

#### 4.1 保留元信息注入

继续保留：

- `applyChapterNavMeta()`
- `installChapterPaginationMeta()`

因为它们已经解决了：

- `next` 卡显示章号
- `dek` 自动从页面摘要提取
- 标题归一化

#### 4.2 修改等高逻辑

`syncChapterPaginationHeights()` 改为只在 wide 版执行。

具体要求：

- 当视口宽度大于 `760px` 时，继续执行等高
- 当视口宽度小于等于 `760px` 时，清除运行时写入的 `style.height`，让卡片回归 `auto`

原因：

- wide 版横排卡片需要等高以形成稳定底边
- thin 版纵向堆叠不需要运行时等高

### 5. 测试更新

`scripts/test-book-pagination-render.sh` 需要同时更新 wide 与 thin 断言。

#### 5.1 wide 断言

应验证：

- `chapter-pagination` 仍使用正文宽度
- `chapter-pagination` 使用双列等分，而不是 `space-between`
- `chapter-nav-card` 不再限制 `max-width: 224px`
- `chapter-nav-card` 不再固定 `height: 80px`
- `chapter-nav-card` 使用 `min-height: 92px`
- 宽卡 `padding`、badge 尺寸、label / title / dek 字号符合新 token

#### 5.2 thin 断言

应验证：

- 容器保持纵向堆叠
- gap 改为 `12px`
- 卡片 `min-height` 为 `92px`
- 卡片 `padding` 为 `12px`
- `next` 卡正文右对齐
- `chapter-nav-badge` 为 `44px`
- 水印尺寸提升到新的 thin token
- 水印在窄屏下恢复可见，并与上下边框保持稳定留白

## 验收标准

### wide 版

- 底部分页严格锚定正文列宽度
- 两张卡在正文列内等宽分布
- 卡片之间的实际视觉间距为 `12px`
- 卡片不再显得过小或漂浮
- `previous` 左对齐，`next` 右对齐
- 双卡底边对齐

### thin 版

- 分页改为上下整宽堆叠
- 卡片像独立章节切换卡，而不是压缩信息条
- `previous` 为左对齐正文
- `next` 为右对齐正文
- 卡片高度、圆标、水印、字号与设计图接近

### 行为与回归

- 上一章 / 下一章链接功能不变
- `next` 卡章节编号继续正确展示
- 无上一章时 wide 版保留占位，thin 版隐藏占位
- `npm run test:site` 通过
- `sh scripts/test-book-pagination-render.sh` 通过

## 风险与缓解

### 风险一：wide 版宽卡导致标题过长时卡片高度明显增长

缓解：

- wide 版保留等高逻辑
- 标题与 `dek` 继续限制为两行

### 风险二：thin 版三列网格导致视觉过度居中或留白过大

缓解：

- 左卡与右卡使用不同的三列模板
- wide / thin 两种断点都只为装饰预留单侧缓冲区，而不是让装饰图覆盖正文或做双侧对称空槽

### 风险三：测试脚本仍锚定旧 token，导致设计更新后假失败

缓解：

- 本次实现必须同步更新测试脚本
- wide / thin 断言分开维护，避免互相污染

5. 运行分页专项测试
6. 运行整站渲染测试

## 最终结论

本次分页问题的根因不是模板，也不是正文宽度本身，而是“分页容器与分页卡片不属于同一套布局模型”。

正确的修复不是继续修 token，而是先统一模型：

- wide 版：正文列内双列等分卡片
- thin 版：正文列内整宽纵向卡片
- JS 等高只保留在 wide 版

在这个模型稳定之后，字号、padding、圆标和水印的像素级细节才有意义，且能稳定贴近设计图。
