## Context

stakeholder 卡片区由 `scripts/shared/homepage-content.mjs` 生成，样式在 `assets/css/landing.discovery.css`，图标资产位于 `assets/icons/stakeholders/`。当前 CSS 已经把每张卡片固定在 `120px` 的盒子中，并提供每个图标各自的尺寸和偏移变量，但当前随仓库发布的 SVG 资源本身的可见边界并不统一。用户随后提供了本地 PNG 源 icon 包 `/Users/edison/Downloads/Project - Africa_Book/icons_pixel_replica_ultra_crisp_png_all/`，它现在是这次变更更高优先级的视觉真值。

在这套源文件出现之前，实施方向是依据截图手工重绘。既然现在已经有了明确的源 PNG，范围更窄、也更可辩护的方案是直接导入这套文件，再让仓库以它为基线进行验证和发布。

## Goals / Non-Goals

**Goals:**
- 直接把用户提供的本地源 icon 包中的 6 个 stakeholder 图标引入项目，作为仓库自持的透明背景 PNG。
- 围绕引入源文件的几何建立项目验证基线，使每个 stakeholder 资产都保持可预测的可见边界，同时让整排渲染后的图标共享同一条水平中心线。
- 保持现有 stakeholder 卡片的 HTML 契约、固定 `120px` 宽度和桌面六列排布，只在需要把图标显示尺寸翻倍时把卡片高度扩展到容纳更大 icon 槽位所需的最小程度。
- 增加能够捕捉“可见边界漂移”的回归校验，而不只是检查文件和 HTML 接线。

**Non-Goals:**
- 重新设计 stakeholder 卡片布局、文案或整个 decision-strip 的构图。
- 把提供的 PNG 重新矢量化或重绘成另一种正式生产格式。
- 在这次变更里重做整个首页 icon 系统，或统一其他首页图标族。
- 在用户已经提供批准源 PNG 包的情况下，再额外重建另一套手工衍生图标。

## Decisions

### Decision: 直接把提供的 PNG 源文件引入仓库
实现将把用户提供的本地 PNG 源 icon 包作为 stakeholder 图标真值，并直接复制到仓库资产路径中。这样既能尊重用户后来提供的更高优先级源文件输入，也能避免再叠加一层手工近似。

Alternative considered:
- 继续保留此前根据截图手工重绘的 SVG 近似稿。Rejected，因为用户后来提供了明确的源 icon 包，并明确要求直接使用它。

### Decision: 以引入源文件为基线统一验证，而不是改写源几何
引入的 stakeholder PNG 保持其原始 `1024x1024` 像素尺寸和透明留白设置。实现不会再把它们重写成新的几何体系，而是把验证锁定到这套源文件裁掉透明边缘后的可见边界上。CSS 仍可做少量光学校正以及按图标轮廓的尺寸均衡，但资产本体继续作为第一真值。

Alternative considered:
- 把引入的 PNG 再重写成新的 SVG 或 `32x32` 规范化集合。Rejected，因为用户明确要求“直接引入”提供的文件，而不是再做一次变换衍生。

### Decision: 保持引入源文件的像素契约
引入的 PNG 已经编码好了单色深蓝线稿、透明背景和可见留白。验证会保持这套源像素契约，而不是在导入过程中再重着色、描摹或重组图层。

Alternative considered:
- 把引入源文件重着色或描摹成新的 house style。Rejected，因为那样项目交付的就不再是用户提供的源文件本体。

### Decision: 用渲染后边界断言锁定几何
验证时会直接读取每个 PNG 的固定像素尺寸，再裁去透明边缘，并断言得到的边界框。对于浏览器最终看到的结果来说，这仍然是最窄但最有效的自动化代理，而且不需要额外经过一次 SVG 光栅化。

Alternative considered:
- 只断言 6 个 PNG 文件存在，或卡片 CSS 仍然使用当前尺寸变量。Rejected，因为这些检查即使通过，也不能保证可见图标仍然保持在引入源集合上。

## Risks / Trade-offs

- [引入源文件使用的是比仓库旧资产更大的 `1024x1024` 光栅画布] -> 验证基于 trim 后的可见边界，而不是继续假设必须是 `32x32` 占位尺寸。
- [PNG 源包同时提供了多个分辨率变体] -> 统一选择 `png_1024_transparent/`，兼顾透明生产资产与避免 `2048` 版本更高的体积成本。
- [引入源文件在 120px 卡片中落地后，仍可能需要少量 CSS 光学校正] -> 先保持 CSS 不动，只有在实际卡片渲染确认需要时才做最小改动。
- [精确 bbox 断言在未来主动替换这套源文件时会显得严格] -> 把测试范围限定在这 6 个图标上，只有在明确批准新的源文件刷新时才更新期望值。
- [当前工作树里已经有其他首页未提交改动] -> 把文件修改范围限制在 stakeholder 资产、最小 CSS/测试触点，以及本次新增的 OpenSpec 文件。

## Migration Plan

1. 更新 OpenSpec，记录“直接导入源 icon 包”的实现方案。
2. 先把几何回归校验切到导入源 PNG 的基线，并验证其能先失败。
3. 从提供的本地源 icon 包导入 PNG 资产，并仅在实际卡片渲染需要时做最小 CSS 调整。
4. 重建站点输出并运行聚焦验证，包括几何检查和站点渲染断言。
5. 如果导入结果不可接受，直接回滚 6 个 PNG 资产、stakeholder 资产引用以及聚焦验证改动；这次变更不涉及任何数据迁移。
