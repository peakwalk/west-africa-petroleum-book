# 图标验收标准

## 适用范围

本文档定义本次变更中基于 trace 的 stakeholder 图标重建工作的验收标准。适用于源图裁切、矢量清理、前端 SVG 交付、PNG 导出以及预览对比资产。

除非后续有明确批准的新变更替代，本文件中的所有标准都属于必过项。

## 验收层级

### Baseline Trace Fidelity Pass

- 用途：候选筛选和截图贴合度验证。
- 这一层主要判断图标是否已经足够贴近截图参考图、结构是否正确、前端语义是否安全、交付包是否完整。
- 通过 `baseline` 代表这套图标适合进入对比、审阅和继续迭代。
- 通过 `baseline` **不等于** 这套图标已经精修到可以作为首页或 topic-card 最终正式交付。

### Production Polish Pass

- 用途：正式精修前端交付。
- 这一层要求先通过 `baseline`。
- 然后再增加更严格的光学精修、stroke 语义、路径经济性和 trace 清理要求。
- 首页、topic-card 等面向用户的正式图标替换，应要求通过 `production`，而不只是通过 `baseline`。
- 自动化 `production` 检查是必要条件，但不是充分条件；最终仍然需要人工视觉复核。

## 通过 / 拒绝规则

- 只有当全部图标通过全部必过项时，整套重建结果才算通过 `baseline`。
- 只有当全部图标通过全部 `baseline` 必过项、全部 `production` 必过项，并通过最终人工复核时，整套重建结果才算通过 `production`。
- 任何一个关键项不通过，都足以拒收整套结果。
- 只要影响轮廓、负形、线条质量或前端可用性，就不能用“差不多”通过。

## 1. 形状一致性

- 重建后的图标外轮廓必须与 `source_reference` 保持一致。
- 内部镂空、负形缺口、封闭孔洞等结构，必须保持与源参考图一致的视觉位置。
- 重建结果必须保留源图的比例关系、重心和视觉重量。
- 不允许把源图标准化成通用 icon library 风格。
- 以 `256px` 叠加对比时，主轮廓可见偏差应控制在 `1px` 以内；次要内部细节偏差应控制在 `2px` 以内。

## 2. 线条粗细、平滑度与光学校正

- 线性图标的线宽在整张图标内必须视觉一致。
- 主要笔画的线宽视觉偏差不得超过 `10%`。
- 曲线必须连续、平滑、自然。
- 在 `400%` 放大检查时，不允许出现台阶状边缘、毛刺、尖刺、抖动或非预期的硬折角。
- 不允许出现断线、意外连线、端点风格不一致等问题。

### `production` 额外要求

- 横梁、中柱、屋檐、盾牌中轴、地球外圆等主结构，必须呈现为经过有意图光学校正的几何，而不是直接继承模糊像素边界。
- 该直的地方必须真正稳定，该圆的地方必须真正顺滑，该对称的地方必须真正对称，不能保留 trace 抖动。
- 自动 trace 只能用于生成草稿，最终交付不得保留直接 trace 的粗糙边。

## 3. 负形与填充正确性

- 透明区域必须是真透明。
- 不允许用白色填充伪装透明镂空。
- 可以使用复合路径、mask、clipPath 或 `fill-rule="evenodd"`，但最终交付结果必须在浏览器中稳定、干净、可预期。
- 实心图标在导出 PNG 后，外轮廓和内部负形必须保持稳定，不能塌陷或粘连。

### 特殊要求：`oil_drop`

- 必须保持深蓝色实心油滴，而不是普通实心水滴。
- 右侧内侧高光切口必须保留为透明负形。
- 这条切口必须从右上内侧向下弯，走势要贴近源参考图。
- 如果这条切口被删除、拉直、加宽过度或直接填死，直接判定拒收。

## 4. 各图标必须保留的关键形状特征

### `regulators`

- 必须清楚保留长横梁、中心节点、两侧秤盘、中柱和底座。
- 中心节点必须有明确存在感。
- 不允许简化成丢失原始比例关系的通用“天平”小图标。

### `governments`

- 必须明确呈现为紧凑的古典政府/神庙建筑。
- 必须保留尖顶屋顶、中间主体、柱子节奏和层次底座。
- 不允许漂移成现代化银行图标或通用法院图标。

### `operators`

- 必须保留中心塔身、底部支撑、侧边设备/平台形状，以及源图中可见的小圆形或环状侧结构。
- 不允许塌缩成简单井架或三角塔架图标。
- 只有在肉眼快速识别时仍明显像同一个源图设备，才可判定通过。

### `shield_star`

- 必须保留盾牌顶部轮廓、底部尖角和居中的紧凑星形。
- 星形不能被放大到破坏盾牌整体平衡。

### `global`

- 必须保留外圆、纬线和经线的整体布局关系。
- 不允许变成实心圆、通用地球符号，或明显不同的经纬线分布。

## 5. 矢量清洁度与路径经济性

- 最终 SVG 必须只包含矢量几何。
- 不允许嵌入位图、base64 图片数据或“外层 SVG 包一张 PNG”的做法。
- 路径必须足够干净，便于前端维护：不能有误描噪点、离散碎片、明显 tracing 杂边。
- 封闭填充图形必须保持正确闭合。
- SVG 中不应保留运行时无关的编辑器私有 metadata。

### `production` 额外要求

- 自动 trace 只能生成 draft，最终交付不得肉眼可见地保留截图模糊边缘带来的微抖动。
- 路径数据应体现为有意图的矢量构造，而不是高密度的 trace 残留。
- 线性主导图标应优先采用 stroke-led 几何，而不是用厚重的复合填充轮廓伪装成线稿。

## 6. 前端交付要求

- 每个图标都必须独立交付为单个 SVG 文件。
- 背景必须透明。
- 线性图标应优先使用：
  - `stroke="currentColor"`
  - `fill="none"`
  - `stroke-linecap="round"`
  - `stroke-linejoin="round"`
  - `vector-effect="non-scaling-stroke"`
- 实心图标应优先使用 `fill="currentColor"`，除非源图要求其他同样干净的矢量表达方式。
- SVG 必须能直接以内联方式用于前端页面。
- SVG 不得依赖编辑器专有命名空间或隐藏资源。

### `production` 额外要求

- `regulators`、`governments`、`shield_star`、`global` 属于线性主导或轮廓主导图标。它们的最终精修交付应为 stroke-led 或同等手工可控的几何，而不是 `evenodd` 填充式 trace 轮廓。
- 如果这些图标仍依赖填充式 tracing 轮廓来表现线稿，它们可以通过 `baseline`，但应当在 `production` 层失败。

## 7. PNG 导出要求

- 每个图标都必须导出透明背景 PNG：`64`、`128`、`256`、`512`、`1024`、`2048`。
- 导出的 PNG 必须保持轮廓、透明区域和负形结构不变。
- 小尺寸导出必须保持可识别且稳定。
- 在 `24px`、`32px`、`64px` 的视觉检查下，图标仍必须清晰，不能出现发糊、发脏、细节粘连。

## 8. 交付包完整性

- 交付包必须包含：
  - `source_reference/`
  - `svg/`
  - `png/`
  - `preview/`
  - `metadata.json`
  - `review_notes.md`
- 文件命名必须稳定、明确，并与图标名称一致。
- 预览资产必须能让审阅者直接比较重建图标和源参考图，无需额外手工处理。

## 9. 验收流程

建议按以下顺序验收：

1. 先运行 `baseline` 自动验收，若失败则直接拒收。
2. 再在对比预览里检查重建图标与 `source_reference` 是否贴近。
3. 再高倍放大每个 SVG，检查轮廓、线宽、平滑度和负形是否正确。
4. 再运行或检查 `production` 自动验收结果。
5. 再进行人工精修复核，重点检查线稿语义、光学校正和 trace 清理是否到位。
6. 最后检查大尺寸和小尺寸 PNG 导出效果。
7. 任一图标未通过当前要求层级下的任一必过项，即整套拒收。

## 10. 直接拒收条件

- 主轮廓与源图肉眼明显不同。
- 内部负形缺失、错位或被填死。
- 线宽明显不均匀。
- 曲线存在明显 tracing 锯齿、毛刺或噪声。
- 结果属于重新设计，而不是基于源图的重建。
- SVG 内包含嵌入式位图数据。
- 小尺寸 PNG 发糊、发脏或难以辨认。

## 11. `production` 额外拒收条件

- 虽然通过了重合度检查，但肉眼仍明显像直接位图描摹。
- 线性主导图标仍以厚重的填充式 tracing 轮廓交付，而不是以可控的 stroke-led 或手工矢量几何交付。
- 主轴线、主圆弧或对称结构仍保留截图模糊边缘带来的可见抖动。
- 人工复核认为它“够像”，但还不够接近设计稿的完成度。
