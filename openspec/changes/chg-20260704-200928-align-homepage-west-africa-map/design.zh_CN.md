## Context

首页地图概览模块由 `scripts/shared/homepage-content.mjs` 生成，并由 `assets/css/landing.discovery.css` 控制样式。当前实现使用 CSS 渐变和裁剪多边形来画地图区域，虽然上线很快，但与用户期望的“西非西海岸政治地图参考图”并不相似。

这次任务刻意收窄范围。目标不是再次整体重做首页，而是让现有地图概览模块在视觉上贴近用户提供的目标图，同时保留当前跳转模型。国家卡片网格仍然是主要入口，地图仍然是次级入口，但它现在必须看起来像批准的西非西海岸政治地图构图。

同一条主要入口路径目前还通过外部 SVG sprite URL 渲染国旗。虽然 Chromium 能正常加载这种写法，但一些独立静态渲染器并不会稳定解析外部 `<use>`。既然国家卡片网格仍是首页主导航面，本次也需要顺手补上这部分的仓库内兼容性修复。

## Goals / Non-Goals

**Goals:**
- 在桌面端尽量贴近已批准的地图概览构图，包括文案密度、蓝色 CTA、佛得角插图圆框和西海岸政治底图。
- 保留地图表面到国家分析页面的现有深链能力。
- 让国家卡片中的国旗在独立首页输出中也能稳定渲染。
- 将改动限制在仓库内、静态构建友好、且只影响首页源码、资源和验证。
- 保持响应式行为，确保模块在平板和手机上仍然可用。
- 让首页断点行为在四个区间内明确且稳定：`0-767` phone、`768-1023` pad、`1024-1439` small desktop、`1440+` desktop locked。

**Non-Goals:**
- 重做国家卡片、专题卡片、Hero 或其他首页模块。
- 引入新的地图框架、GIS 依赖或动态运行时。
- 在本次改动中加入丰富 hover 提示或第二层石油元数据。
- 如果会拖慢交付，就不在本次把地图重建为完全语义化的矢量地理图。

## Decisions

### Decision: 使用仓库内、源自参考图的地图面板图片作为视觉基线
右侧地图面板将使用一个由批准参考图裁出的、归仓库管理的地图图片作为视觉基线。这是在不引入外部地理数据流水线、也不手绘脆弱 SVG 的前提下，实现用户所要求像素级对齐的最直接方式。

Alternative considered:
- 立即用纯 CSS/SVG 重建地图。拒绝原因：本次改动里这样做更慢、风险更高，而且第一次就精确贴合参考构图的概率更低。

### Decision: 用覆盖在参考图上的可聚焦热点保留跳转能力
地图面板本身将不再渲染一层可见的实时旗帜 DOM。相反，会在参考面板中的旗帜位置上叠加透明、可聚焦的热点，以保留现有国家跳转模型。这样既能保持与首页国家卡片一致的目标路由，又能让可见画面锁定到批准参考图。

Alternative considered:
- 在参考面板之上再渲染一层可见旗帜。拒绝原因：会造成与参考图的视觉漂移，并引入第二轮人工光学校准。

### Decision: 所有文案与结构改动都放在首页生成源码里，而不是直接改产物
新的标题、描述、CTA 标记和地图面板结构都将写入 `scripts/shared/homepage-content.mjs`，再通过构建重生成 `index.html` 和 `public/`。这符合仓库“不要手工维护生成 landing 输出”的规则。

Alternative considered:
- 直接改 `index.html`。拒绝原因：会和源生成器脱节，并在下次重建时被覆盖。

### Decision: 在首页 HTML 中内联一次共享国旗 sprite
首页生成器会把共享国旗 sprite 定义直接嵌入页面，并让国家卡片里的 `<use>` 指向 `#nigeria` 这样的本地片段 ID。这样既保留现有视觉系统，也去掉了首页主卡片网格对外部 sprite 解析的依赖。

Alternative considered:
- 继续保留 `/assets/icons/country-flags.svg#...` 引用。拒绝原因：外部 SVG symbol 在部分独立静态预览环境里的解析并不稳定，会让国家卡片看起来损坏，即使路由本身仍然可用。

### Decision: 仅给该模块加局部蓝色 CTA，而不是改全局主按钮 token
批准参考图里的该模块 CTA 是蓝色，而当前首页更大范围仍然使用橙色主按钮。实现上会只给地图概览模块应用局部蓝色 CTA 处理，而不会改掉整个 landing 页的全局主按钮样式。

Alternative considered:
- 全局修改 `.button-primary`。拒绝原因：会意外影响 Hero、搜索、页脚等超出本任务范围的 CTA。

### Decision: 将首页响应式行为收口到四个命名区间
首页将把 `0-767` 视为 phone，`768-1023` 视为 pad，`1024-1439` 视为 small desktop，`1440+` 视为 desktop locked。现有首页特定断点（如 `700`、`900`、`1100`、`1200`、`1201`）要么被移除，要么被收窄，使主要布局切换只发生在约定区间边界。

在 locked desktop 区间内，当前仍会随视口继续放大的关键首页字号与间距将被冻结到稳定值。这样可以避免“桌面更宽反而多换一行”或 Hero 指标继续变大的问题，而此时列布局本身其实已经基本固定。

Alternative considered:
- 保留当前桌面流体字号，只单独修补地图标题。拒绝原因：用户已经明确要求按 phone/pad/desktop 建立更清晰的规则，而地图标题问题只是更广泛断点一致性问题的一个暴露点。

## Risks / Trade-offs

- [源自参考图的栅格资源可能在未来国家集或旗帜更新后漂移] -> 将热点路由数据与图片分离，确保即使未来更换底图，导航契约仍可独立维护。
- [栅格图在超大屏幕上可能变软] -> 使用足够大的源资源，限制区块宽度，并保持等比缩放而非拉伸。
- [透明热点不像可见交互标记那样直观] -> 增加 hover/focus 外框，让鼠标和键盘用户仍然得到清晰提示。
- [内联 sprite 会略微增加首页 HTML 体积] -> 接受这点小幅增长，因为同一份 sprite 会被所有国家卡片复用，同时能消除更明显的渲染故障。
- [法语首页可能共享部分 landing CSS] -> 将选择器限制在地图概览模块，并验证本地化生成输出仍然正常。
- [断点收口可能意外影响首页其他模块] -> 只对首页相关选择器应用显式区间锁定；仅在确有必要时保留微型手机修正；并在代表性宽度上验证构建后的首页。

## Migration Plan

1. 为首页地图对齐改动补齐 OpenSpec 文档和参考资源。
2. 只修改首页内容生成源码与局部 CSS。
3. 重建首页/站点输出，让生成的 `index.html` 和 `public/` 反映改动。
4. 运行针对性的站点验证，并抓一张更新后地图概览模块的本地截图，与批准参考图做比较。
5. 如果结果不满意，直接回滚新增资源以及该模块的模板/CSS 改动；本次没有持久化数据迁移。
