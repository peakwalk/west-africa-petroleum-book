## Context

这次首页重做的直接依据，是已经下载到 `resources/version2/` 的 UA-11 Version 2 材料，以及当前 landing page 的实现位置：`editions/en/site/index-main.html`、`editions/fr/site/index-main.html`、`scripts/generate-index-page.mjs`、`scripts/shared/landing-shell.mjs` 和 `assets/css/landing.css`。

这些材料描述的是一版更清晰的首页：导航更直接、以国家为主的探索层、按主题浏览层、仅搜索图书的搜索层，以及更强的更新/联系信号。当前首页并不符合这个模型。它仍然把多种进入方式混在一起，保留了已经过时的顶层导航项，也没有把国家入口做成最突出的探索面，和产品“西非石油参考入口”的定位并不一致。

如果按第一性原理拆解，这个首页其实只需要回答 5 个问题：
- 这是什么参考资源，我为什么应该信任它？
- 我现在可以看哪个国家？
- 我现在可以看哪个主题？
- 如果我只想找一个具体事实，最快怎么找？
- 这些内容是不是新的，我怎么联系团队？

这 5 个问题彼此独立，合起来又完整覆盖这个页面的职责。因此首页结构也应当一一对应，而不是让多个区块重复争夺同一类意图。

repo 的技术形态也决定了解法边界。站点是静态生成的，landing page 是 repo 自己维护的模板，书内搜索已经存在于 mdBook reader 中，chapter 3 也已经提供了可供国家卡片直达的锚点。设计应该利用这些现成事实，而不是凭空引入新的运行时系统。

## Goals / Non-Goals

**Goals:**
- 交付一套明显围绕“定位说明、国家发现、主题发现、书内搜索、可信度/更新/联系”来组织的首页信息架构。
- 用 16 张统一规格的国家卡片加一个辅助性西非地图，把国家入口做成首页最主要的探索路径。
- 复用现有静态图书路由、章节目标和 mdBook 搜索，而不是额外建设独立搜索或数据后端。
- 用 `Latest Updates`、更清晰的 coverage 信号和直接联系入口，替换当前低信号的首页模块。
- 把首页控制的数据集中管理，避免字符串和深链分散在多个模板里。
- 完整交付英文首页主体改版，同时通过共享 shell 保持法文首页可用。

**Non-Goals:**
- 在本次 change 中完整重做法文首页主体。
- 引入动态的数据库驱动国家统计服务。
- 在现有书内搜索之外再做一套全站搜索。
- 改动章节正文、章节 URL 或底层 mdBook 内容模型。
- 如果交互复杂度或移动端成本过高，就不在 Phase 1 强行加入地图 hover 细节弹层。

## Decisions

### Decision: 按 5 个互不重叠的意图区组织首页
首页将围绕 5 个意图区来组织，分别直接回答上面的第一性原理问题：
- orientation：hero、定位文案和 current-edition CTA
- country discovery：国家卡片和地理地图
- topic discovery：`Browse by Topic`
- fact lookup：`Search Upstream Atlas`
- trust and next steps：`Latest Updates`、`Current Edition`、`Future Development`、footer coverage 和 contact

这样首页结构就是 MECE 的。国家卡片不再和主题卡片争夺同一职责。搜索不再伪装成主题浏览。最新更新不再重复作者介绍。footer coverage 也不再承担第二套主导航的职责。

考虑过的替代方案：
- 保留当前首页，只局部修补一些区块。否决，因为现在的问题是结构性问题，不是视觉细节问题；局部修补只会保留原来的重叠心智模型。

### Decision: 把国家发现做成首页最主要的进入路径
首页会把按国家进入作为最主要的探索面，因为产品核心承诺是“西非范围内的石油地理与国家情报参考”。因此 `Coverage Across West Africa` 区块会直接展示 16 个目标国家的统一卡片，并在卡片中包含一致的尺寸规格、状态标识、主管 ministry / NOC 信息、规模指标，以及进入 chapter 3 对应国家小节的 CTA。

政治地图只是辅助导航，不是第二套主信息模型。它提供地理上的直觉入口，但必须和国家卡片指向同一批国家目标，这样系统中只有一份国家路由真值。

考虑过的替代方案：
- 把地图做成国家发现的主入口，把卡片当成可选补充。否决，因为地图在移动端可读性更差，也不如统一卡片网格适合做横向比较。

### Decision: 把主题浏览和搜索保持为两个不重叠的系统
`Browse by Topic` 负责把用户带到精选主题章节。`Search Upstream Atlas` 负责自由检索整本在线图书。这两个模块解决的是不同问题，应该明确分开。

本次重做会把 `Explore the Reference Library` 改名为 `Browse by Topic`，并连接到 Version 2 材料中已经批准的章节目标。搜索区会明确说明它搜索的只是在线图书，而不是全站或外部内容。

考虑过的替代方案：
- 把主题浏览和搜索合并成一个泛化的发现区。否决，因为“精选浏览”和“精确查找”对应的是不同意图，会带来不同的用户预期。

### Decision: 复用现有静态搜索和章节路由
repo 已经有 canonical 的图书章节 URL、chapter 3 的国家锚点，以及 mdBook reader 的搜索索引。首页重做会直接复用这些现成能力，而不是再引入新的搜索后端或内容服务。这样实现方式才和当前静态构建链一致，也避免制造第二套搜索真相来源。

考虑过的替代方案：
- 再做一套首页专用搜索并绑定自定义数据集。否决，因为这会增加运行时复杂度，但 Phase 1 并没有新的用户问题需要它来解决。

### Decision: 用 repo 自己维护的结构化配置驱动首页内容
这次重做涉及一批会独立于布局代码变化的数据：16 个国家卡片、主题目标、latest updates、footer coverage 文案，以及共享 shell 字符串。这些信息应该放在 repo 自己维护的结构化内容源里，让模板和脚本都从同一份规范数据渲染。

考虑过的替代方案：
- 把所有新内容直接硬编码进 `index-main.html`。否决，因为后续改文案和改链接都会变得脆弱，还会让路由真值散落在标记层。

### Decision: 先交付英文主体改版，把法文影响限制在共享 shell 兼容层
UA-11 Version 2 材料对完整首页结构的定义目前是英文优先的。因此本次 change 会完整交付英文首页主体改版，同时把法文改动限制在共享 shell、locale-safe 路由和对新架构的兼容上。法文首页必须继续可用，且不能继承断裂锚点、缺失目标或英文独占的 shell 回归。

考虑过的替代方案：
- 在同一个 change 里强行做完整双语首页改版。否决，因为法文主体的设计方向和审批材料并没有与英文一样成熟，这会明显扩大范围和风险，但并不能帮助英文版先上线。

### Decision: 地图先做成可点击基线，富交互 hover 行为后置
Phase 1 需要的是地理浏览能力，而不是复杂交互式数据应用。因此地图基线会是一张可点击的政治地图，路由到和国家卡片相同的目标。hover 弹层和自动生成的国家统计继续保留为可选的 Phase 2 增强项。

考虑过的替代方案：
- 在 rich hover popups 准备好之前阻塞整个改版。否决，因为 Phase 1 的核心价值是“快速进入国家内容”，不是“高级地图交互”。

## Risks / Trade-offs

- [国家元数据可能和章节目标漂移] -> 卡片和地图共用一份结构化路由源，并在站点断言里验证代表性国家链接。
- [英文优先发布可能造成 EN/FR shell 分叉] -> 共享导航、footer 动作和 locale 切换行为继续走公共生成代码，并同时验证两个 edition。
- [用户可能把搜索理解成全站搜索] -> 区块明确标注为 `Search Upstream Atlas` 且仅搜索在线图书，并复用现有图书搜索目标面。
- [复杂地图会拖累可访问性和移动端体验] -> 地图只做国家卡片的辅助入口，并要求卡片网格始终提供等价导航。
- [Latest Updates 如果只是静态装饰会很快过时] -> 把更新项放进结构化内容源里，让它能独立于布局代码维护。

## Migration Plan

1. 先补齐首页信息架构相关的 OpenSpec 工件，并把范围边界写清楚。
2. 引入结构化的首页内容源，覆盖国家、主题、更新和 footer coverage。
3. 更新共享 landing shell、导航动作以及 contact/search 的接线方式。
4. 在英文首页中实现新的 hero、国家、主题、搜索和信任信号区块。
5. 通过共享 shell 和路由更新保持法文首页兼容，而不强行同步完整主体改版。
6. 更新 site 断言，重新构建站点，并人工检查代表性的英文与法文首页输出。
