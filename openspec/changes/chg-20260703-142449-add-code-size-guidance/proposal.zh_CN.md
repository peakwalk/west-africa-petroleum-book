## 为什么

当前仓库的 `AGENTS.md` 已经定义了工作流、验证和本地化规则，但还没有为手写源码文件提供任何行数指导。这会让代理在样式表、模板或生成脚本持续膨胀时缺少仓库级约束。结果很直接：可审查性下降，局部改动更难隔离，像落地页样式这样的大文件会不断吸纳不相关职责。

参考仓库 `oae-mono` 已经用显式的文件大小规则解决了这个问题。Africa Book 也需要同类规则，但要适配本仓库的实际对象：一般性的手写源码文件，以及尤其容易膨胀的落地页样式、模板和页面生成脚本。

## 变更内容

- 在 `AGENTS.md` 中增加面向手写源码文件的仓库级文件大小指导规则。
- 在 `AGENTS.zh_CN.md` 中加入语义对齐的简体中文规则。
- 在现有 `agent-workflow-governance` 能力下通过 OpenSpec 固化该政策，为后续工作流规则调整提供持久契约。

## 能力

### 修改的能力
- `agent-workflow-governance`：仓库工作流契约现在增加了面向手写源码文件的、以可审查性为目标的行数指导，以及对已超限文件的编辑要求。

## 影响

- 受影响文档：`AGENTS.md`、`AGENTS.zh_CN.md`
- 新增 OpenSpec 变更文档位于 `openspec/changes/chg-20260703-142449-add-code-size-guidance/`
- 不直接修改书稿内容、生成站点输出、图表资源或落地页行为
